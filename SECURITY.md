# Security

## Reporting a vulnerability

**Please do not report security vulnerabilities through public GitHub issues.** Public issues are visible to everyone and can put users at risk before a fix exists.

### How to report

Use GitHub’s **private vulnerability reporting** for this repository:

1. Open the repository on GitHub.
2. Go to **Security** → **Report a vulnerability** (or use GitHub’s [private reporting guidance](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)).

That opens a **private** channel so maintainers can assess impact and coordinate a fix without disclosing details prematurely.

### What to include

- A short description of the issue and where it lives (for example: GitHub Action, a specific package path, or a documented workflow).
- Steps to reproduce, or enough technical detail for us to reproduce.
- If you can, your assessment of impact (confidentiality, integrity, availability).

### What to expect

- We aim to **acknowledge** private reports within **about one calendar week**. This is a best-effort target for a small maintainer team, not a contractual SLA.
- We will work with you on **coordinated disclosure** when a fix is ready (including credit if you want it).
- This project does **not** offer a paid bug bounty unless explicitly stated elsewhere.

If private reporting is unavailable to you for some reason, contact the maintainers through an appropriate **non-public** channel; do not post exploit details in public issues or discussions.
